# SQL Antipatterns

Common relational schema and query design mistakes, one skill per antipattern
— engine-agnostic, applies regardless of which SQL database you're using.
Each skill covers how to recognize the antipattern, why it causes problems,
any legitimate exceptions, and the preferred fix.

## Install

```bash
npx skills add mihailtd/skills/skills/sql-antipatterns --all
```

Add `-g` to install globally instead of per-project. Use `--skill <name>`
(repeatable) instead of `--all` to cherry-pick individual skills from this
package, e.g.:

```bash
npx skills add mihailtd/skills/skills/sql-antipatterns --skill sql-antipatterns-jaywalking
```

## Skills (31)

- **[sql-antipatterns-jaywalking](sql-antipatterns-jaywalking/SKILL.md)** — Detects and fixes the Jaywalking antipattern — storing a multivalue or many-to-many relationship as a comma-separated list of IDs in a single column — by replacing it with a proper intersection table.
- **[sql-antipatterns-naive-trees](sql-antipatterns-naive-trees/SKILL.md)** — Detects the Naive Trees antipattern — modeling hierarchical data with only a parent_id Adjacency List and fighting SQL to fetch arbitrary-depth ancestors/descendants — and guides toward recursive CTEs, Path Enumeration, Nested Sets, or Closure Table based on the access pattern.
- **[sql-antipatterns-works-on-my-computer](sql-antipatterns-works-on-my-computer/SKILL.md)** — Flags dev/production database version and configuration drift that causes SQL to work locally and fail on deploy, and recommends matching database versions and settings across environments.
- **[sql-antipatterns-id-required](sql-antipatterns-id-required/SKILL.md)** — Detects the ID Required antipattern — treating "primary key" as always meaning an auto-increment id column, which lets intersection tables silently accept duplicate rows — and guides toward primary keys tailored to what actually identifies each row (natural, compound, or pseudokey).
- **[sql-antipatterns-keyless-entry](sql-antipatterns-keyless-entry/SKILL.md)** — Detects the Keyless Entry antipattern — skipping foreign key constraints and trying to enforce referential integrity in application code instead — and guides toward declaring FOREIGN KEY constraints with appropriate ON UPDATE/ON DELETE actions.
- **[sql-antipatterns-entity-attribute-value](sql-antipatterns-entity-attribute-value/SKILL.md)** — Detects the Entity-Attribute-Value (EAV) antipattern — a generic entity/attribute-name/attribute-value table faking a flexible schema — and guides toward Single/Concrete/Class Table Inheritance or a JSON column instead.
- **[sql-antipatterns-polymorphic-associations](sql-antipatterns-polymorphic-associations/SKILL.md)** — Detects the Polymorphic Associations antipattern — a dual-purpose foreign key plus a string column naming which parent table it points to, so no real FOREIGN KEY constraint can exist — and guides toward reversed per-parent intersection tables or a common supertable.
- **[sql-antipatterns-multicolumn-attributes](sql-antipatterns-multicolumn-attributes/SKILL.md)** — Detects the Multicolumn Attributes antipattern — a multivalue attribute spread across several numbered columns (tag1, tag2, tag3) on one table — and guides toward a dependent table with one row per value.
- **[sql-antipatterns-storing-prices](sql-antipatterns-storing-prices/SKILL.md)** — Clarifies when storing a seemingly-redundant value (like an order's price) alongside a reference to its current source is correct — capturing a point-in-time fact on an association table, not a normalization violation.
- **[sql-antipatterns-metadata-tribbles](sql-antipatterns-metadata-tribbles/SKILL.md)** — Detects the Metadata Tribbles antipattern — cloning tables or columns per distinct data value (Bugs_2021, Bugs_2022) to keep tables small, which forces new data to require new schema — and guides toward horizontal/vertical partitioning or a proper dependent table.
- **[sql-antipatterns-rounding-errors](sql-antipatterns-rounding-errors/SKILL.md)** — Detects the Rounding Errors antipattern — using FLOAT/REAL/DOUBLE PRECISION for money or other exact fractional values, which silently rounds and breaks equality comparisons and sums — and guides toward NUMERIC/DECIMAL instead.
- **[sql-antipatterns-31-flavors](sql-antipatterns-31-flavors/SKILL.md)** — Detects the 31 Flavors antipattern — baking a fixed set of allowed values into a column's metadata via ENUM or a CHECK constraint — which makes adding, renaming, or retiring values require schema changes — and guides toward a lookup table with a foreign key instead.
- **[sql-antipatterns-reserved-words](sql-antipatterns-reserved-words/SKILL.md)** — Explains SQL syntax errors from using a reserved keyword (order, from, table, ...) as an unquoted identifier, and how to fix them with delimited identifiers or a rename.
- **[sql-antipatterns-phantom-files](sql-antipatterns-phantom-files/SKILL.md)** — Detects the Phantom Files antipattern — storing images/media as external files with only a pathname column — which loses COMMIT/ROLLBACK guarantees, garbage collection, backup coverage, and access control — and guides toward a BLOB column when those guarantees matter.
- **[sql-antipatterns-index-shotgun](sql-antipatterns-index-shotgun/SKILL.md)** — Detects the Index Shotgun antipattern — adding or removing indexes by guesswork (none, too many/every permutation, or ones no query can use) instead of measurement — and guides toward the MENTOR methodology (Measure, Explain, Nominate, Test, Optimize, Rebuild).
- **[sql-antipatterns-fear-of-the-unknown](sql-antipatterns-fear-of-the-unknown/SKILL.md)** — Detects the Fear of the Unknown antipattern — treating NULL as an ordinary value or vice versa in arithmetic, concatenation, equality, and NOT IN lists, where three-valued logic silently produces wrong results — and guides toward IS NULL, IS DISTINCT FROM, COALESCE(), and deliberate NOT NULL constraints.
- **[sql-antipatterns-ambiguous-groups](sql-antipatterns-ambiguous-groups/SKILL.md)** — Detects the Ambiguous Groups antipattern — selecting a non-grouped, non-aggregated column in a GROUP BY query and hoping the database infers it from the row with MAX()/MIN() — and guides toward window functions, correlated subqueries, derived tables, or outer joins that make "row with the extreme value per group" explicit.
- **[sql-antipatterns-portable-sql](sql-antipatterns-portable-sql/SKILL.md)** — Cautions against restricting SQL to a hoped-for portable common subset across database brands — it both fails (vendors diverge even on standard features) and forgoes each brand's genuinely useful proprietary features — and recommends an Adapter-pattern abstraction layer instead.
- **[sql-antipatterns-poor-mans-search-engine](sql-antipatterns-poor-mans-search-engine/SKILL.md)** — Detects the Poor Man's Search Engine antipattern — using LIKE '%word%' or regex for keyword search, which forces a full table scan and produces false substring matches — and guides toward vendor full-text indexing, a dedicated search engine, or a hand-built inverted index.
- **[sql-antipatterns-spaghetti-query](sql-antipatterns-spaghetti-query/SKILL.md)** — Detects the Spaghetti Query antipattern — forcing a complex multi-part report into one monolithic query, which silently produces unintended Cartesian products that multiply counts together — and guides toward splitting into several simpler, independently-correct queries.
- **[sql-antipatterns-implicit-columns](sql-antipatterns-implicit-columns/SKILL.md)** — Detects the Implicit Columns antipattern — using SELECT * or column-less INSERT — which silently breaks when columns are added, dropped, renamed, or reordered, and wastes bandwidth — and guides toward always naming columns explicitly.
- **[sql-antipatterns-readable-passwords](sql-antipatterns-readable-passwords/SKILL.md)** — Detects the Readable Passwords antipattern — storing passwords in plain text (or any reversible form) so they can be recovered/emailed back — and guides toward a salted cryptographic hash, password reset instead of recovery, and keeping plaintext out of SQL statements entirely.
- **[sql-antipatterns-sql-injection](sql-antipatterns-sql-injection/SKILL.md)** — Detects SQL Injection — building SQL by concatenating or interpolating unvalidated data (including data read back from the database) into the query string — and guides toward query parameters for values, whitelist mapping for identifiers/keywords, and filtering everywhere else.
- **[sql-antipatterns-pseudokey-neat-freak](sql-antipatterns-pseudokey-neat-freak/SKILL.md)** — Detects the Pseudokey Neat-Freak antipattern — treating gaps in an auto-generated primary key as a problem to fix by reusing or renumbering values — which risks race conditions and breaks external references — and guides toward accepting gaps and using ROW_NUMBER() (with PARTITION BY for per-group numbering) when a gap-free number is actually needed.
- **[sql-antipatterns-see-no-evil](sql-antipatterns-see-no-evil/SKILL.md)** — Detects the See No Evil antipattern — ignoring database API error/exception returns, and debugging by reading the code that builds SQL instead of the generated SQL text itself — and guides toward checking every call's outcome and always inspecting the literal query (and its error message) when debugging.
- **[sql-antipatterns-diplomatic-immunity](sql-antipatterns-diplomatic-immunity/SKILL.md)** — Detects the Diplomatic Immunity antipattern — treating database code as exempt from the documentation, version control, and testing discipline applied to application code — and guides toward documenting the schema, versioning database artifacts with migration tooling, and testing database structure and behavior directly.
- **[sql-antipatterns-renaming-things](sql-antipatterns-renaming-things/SKILL.md)** — Explains why renaming a live table or column is a chicken-and-egg deployment problem, and gives two zero-downtime techniques: dual-write-then-migrate, or a compatibility view aliasing the old name.
- **[sql-antipatterns-standard-operating-procedures](sql-antipatterns-standard-operating-procedures/SKILL.md)** — Detects the Standard Operating Procedures antipattern — defaulting to stored procedures for all database logic by inherited habit rather than evaluating the project's actual architecture — which concentrates load on a non-scalable database server and is hard to develop/test/deploy safely; covers MySQL-specific limitations in depth.
- **[sql-antipatterns-foreign-key-mistakes-standard-sql](sql-antipatterns-foreign-key-mistakes-standard-sql/SKILL.md)** — Checklist of standard-SQL foreign key mistakes: wrong reference direction, table creation order, referencing a non-key column, splitting/misordering a compound key, mismatched types/collations, orphaned data, SET NULL on NOT NULL, duplicate constraint names, and mismatched table types.
- **[sql-antipatterns-foreign-key-mistakes-mysql](sql-antipatterns-foreign-key-mistakes-mysql/SKILL.md)** — Checklist of MySQL-specific foreign key mistakes: mismatched/unsupported storage engines (silently dropped constraints), keys on BLOB/TEXT/JSON, non-unique/left-most-subset index references, silently-ignored inline REFERENCES syntax, unsupported implicit referenced columns, and TEMPORARY/PARTITIONED table restrictions.
- **[sql-antipatterns-normalization](sql-antipatterns-normalization/SKILL.md)** — Reference for the rules of relational normalization: what makes a table a true relation, first through fifth normal form plus Boyce-Codd/Domain-Key/sixth normal form, and the common myths (normalization isn't about performance, pseudokeys, or "separating everything"). The theoretical backing behind most of the other skills in this package.
