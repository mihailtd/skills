# Business Analysis

Domain storytelling and scope-definition techniques for translating business processes into requirements and user stories.

## Install

```bash
npx skills add mihailtd/skills/skills/business-analysis --all
```

Add `-g` to install globally instead of per-project. Use `--skill <name>` (repeatable) instead of `--all` to cherry-pick individual skills from this package, e.g.:

```bash
npx skills add mihailtd/skills/skills/business-analysis --skill business-analysis-domain-stories-to-requirements
```

## Skills (4)

- **[business-analysis-domain-stories-to-requirements](business-analysis-domain-stories-to-requirements/SKILL.md)** — Guides the transformation of Domain Storytelling models into actionable requirements, user stories, and a structured backlog using user story mapping.
- **[business-analysis-domain-storytelling-finding-subdomains](business-analysis-domain-storytelling-finding-subdomains/SKILL.md)** — Guides the use of Domain Storytelling heuristics to identify subdomains, define bounded contexts, and align team boundaries with software architecture.
- **[business-analysis-domain-storytelling-user-story-mapping](business-analysis-domain-storytelling-user-story-mapping/SKILL.md)** — Guides the combination of Domain Storytelling with User Story Mapping to connect domain scenarios with agile backlog structure and product planning.
- **[business-analysis-scope](business-analysis-scope/SKILL.md)** — Guides the definition of story scope in Domain Storytelling using granularity, point-in-time, and domain purity to explore and drill into domains effectively.
